# 音频有效性校验（ASR）

**代码位置**：`director/asr_check.py` + `director/routes_asr.py`（前端：`web/js/editor/mixins/asr_check.js`、`web/js/minimax_image_batch.js`）

**r2v 工具栏**「提取音频」旁边有一个「音频有效性校验」按钮：点它 → 选缓存来源（一采 / 二采）+
勾片段 → 后端按这些片段**当前**的提示词核对它们**已缓存**的音轨。整个过程不重新生成任何片段，
**也不需要为了它跑一次节点**。

结果写在每张卡片的预览区里：**「一采 / 二采 / 音频」右边新增的「识别」页签**（校验结束后会自动跳过去）。
每张卡片显示的是**它自己那一段**的内容：

```
片段 3 · 一采 · 20:59:35 · 音频 1.00–3.00s
本段提示词台词（2 条）
  S1   我将用最简单最直接最不绕弯子。
  S2   哈哈哈，当然可以吃啦。三步之内，必有解药，以毒攻毒！
本段识别到（2 段）
  S1 → S1   我将用最简单、最直接、最不绕弯子。
  S3 → S2   好的，当然可以吃了                     （提示词里没有这个说话人）
整批判定（说话人跨片段合并计分）
  音频有效性校验 (ASR) … - 综合判定: 不通过（阈值 25%，最高 43.1%）
```

- 「本段识别到」里的 `S3 → S2` 是识别器自己的编号 → 按名次映射到的提示词说话人；映射不上或
  `S00`（未归类）的行标黄，并写明原因。
- 本段该说话、却没识别到的说话人会单列一行「本段应该说话、但没识别到：S2」——「漏识」在这里一眼可见。
- 时间窗归属：校验音频是各段**顺序拼接**的，识别段按与哪一段的时间区间重叠最多来归属
  （`segment_asr_details`），所以每张卡片才能只显示自己那一段。
- **整批报告仍然保留**在下面：说话人是跨片段合并计分的，错误率只能给整批，不能拆到段。
- 不在本次核对范围内的卡片只写明范围，不再重复贴整批报告。
- 只有「当前视图里根本没有预览区」（例如纯缩略图视图）时才退回弹窗，避免结论无处可看；校验**失败**时
  除了写进页签也会弹一次窗，因为那一步需要人去改配置。

## 前置条件

| 项 | 值 |
|---|---|
| 模型类型 | `T8_MOSS_TRANSCRIBE_MODEL` |
| 来源 | `Comfyui-MOSS-Transcribe-Diarize-T8`（与本包放在同一个 `custom_nodes` 下），用 `T8_MOSS_ModelLoader` 的 `model` 口接入 |
| 触发 | r2v 工具栏「音频有效性校验」按钮（非 r2v 任务不显示） |
| 路由 | `POST /minimax/director_opt/asr_check_status`（可用性探测）、`POST /minimax/director_opt/asr_check`（校验）；两者都带 `source` = `1st` / `2nd` |

### 模型句柄从哪来

转写需要的是「模型句柄」，而它并**不是**已载入的权重：`T8_MOSS_ModelLoader` 只解析模型目录并记录
推理设置（设备 / 精度 / 显存驻留策略 / attention 后端），权重到 `run_transcription` 时才惰性载入。
因此句柄有两级来源：

1. **接线的**——把 `asr_model` 口接上并**运行过一次**节点，节点会把当时的句柄登记到
   `director/asr_runtime.py`，按钮优先用它（即沿用你自己的加载器设置）。重启 ComfyUI 会清掉登记，
   需重跑一次；
2. **自动构造的**——没有登记时，`routes_asr` 直接调用 T8 加载器节点自己的 API，用它的默认参数
   （`device=auto`、`precision=auto`、`memory_policy=keep`、`verify_hashes=False`）构造句柄。
   不下载、不动 GPU（只读模型目录做校验与指纹，实测约 1~2 秒，结果进程内缓存）。
   弹窗里会有一行灰字说明「正在用默认参数」，接线并跑一次即可换成你自己的设置。

两级都失败（例如本地根本没有模型文件、transformers 版本不满足）时才会提示「没有可用的 ASR 模型」，
并把失败原因写在第二行。未接模型**不影响出片**；校验本身抛错也只体现在弹窗文案里。

## 它做了什么

1. 弹窗打开（以及切换缓存来源）时先调 `/asr_check_status`：**没有该来源音轨缓存的片段直接置灰不可选**，
   并在标题下写明该来源有几段可用、模型是否就绪；
2. 只取**勾选**的那些片段**该来源**的音轨缓存；
3. 按时间轴顺序拼成一整条，用带说话人分离的 ASR 转写；
4. 从这些片段**当前**的提示词里读出**台词块**，逐说话人与识别结果比对：错误率 + 说话人是否对得上；
5. 把结论写进预览区的「识别」页签并切过去（见上）。

探测与校验在 Python 侧走的是同一个读取函数（`routes_asr._read_audio` →
`load_segment_audio_by_position`），所以「显示可选」和「点了能跑」不会不一致。该读取**按位置**而不是
指纹取文件——缓存指纹包含 `prompt`，若按指纹判断，改完提示词再核对就会误报「没有缓存」，而那正是本功能
最主要的用法。

## 台词写法

必须严格写成下面这个格式（`re` 必须整段匹配，格式不对就当普通文本）：

```
<Subject 1> (S1) says: <d>[Chinese] 师尊，你一直说你是毒修。</d>
```

| 片段 | 含义 |
|---|---|
| `<Subject N>` | 哪个参考主体在说话 |
| `(SN)` | 这条台词属于哪个说话人 |
| `<d>[lang]…</d>` | 台词正文与语言标签 |

前端会把合法台词渲染成带框的说话人卡片；不合法的不渲染、也不参与校验 —— 写错一个字符只会让
校验跳过这句，不会悄悄变成一条要求。

> 后端的 `SPEECH_RE` 与前端 `minimax_prompt_mentions.js` 里的 `SPEECH_RE` 没有共享代码，
> 改动必须两边同步。

## 长音频

拼接后超过 **30 秒**（`LONG_AUDIO_SECONDS`）会自动改走分块长音频识别
（`runtime.long_audio`），避免一次性识别丢掉尾部语音（那会被误判成「这句台词没说」）。
报告里会写明本次走的是哪条路径；即便走长音频路径，若结果仍被标记 `possibly_truncated`，
报告也会提示。

## 说话人怎么对号入座

识别器按**它自己**的首次出现顺序给说话人编号，与提示词里介绍的顺序无关。因此按「排名」配对：

1. 提示词的说话人按首次出现的台词排序；
2. 识别结果的说话人按首次发声排序；
3. 第 i 名对第 i 名。

`S00` 是「未分配到说话人」标记，**不是**第 0 个人：它不参与排名，单独报告为「未知说话人」，
否则会把所有真实说话人整体错位一位。

## 打分

- 逐说话人、无对齐：该说话人的期望台词按提示词顺序拼接，与该说话人的识别文本按时间顺序比较。
- 错误用 Levenshtein 编辑距离算，token 规则是 **CJK（含假名、谚文）一个字符一个 token**，
  拉丁字母 / 数字连续串算一个 token —— 中文得到 CER，英文得到 WER，且不依赖分词器。
- **标点（含全角 `，、。！？`）一律丢弃**，既不切 token 也不计错：期望写「毒，在我之上。」而识别成
  「毒在我之上，」依然是 0 错误。
- 错误率 = 编辑距离 / 期望 token 数。中文下分母就是**期望台词的字数**。
- 不达标的一行会附上错误类型拆解：`— 替换 x、漏识 y、多出 z`。**漏识多通常不是「听错了」，而是识别器把
  这段丢了或判给了别的说话人** —— 对照上面的「多余说话人」，报告会列出它识别到的内容。
- 「多余说话人」的文本**不参与**任何判定（它没有可比的期望台词），只作为排查线索展示。
- 阈值 `PASS_RATE = 0.25`：错误率 ≤ 25% 视为这句说对了。
- 期望文本为空的说话人直接跳过（不给免费通过）。

## 读取报告

结论追加在 `report` 末尾，典型内容：

```
音频有效性校验 (ASR): 分块长音频识别 (48.2s > 30s)
  S1: 错误率 12.5% — 通过
  S2: 错误率 41.7% — 未达标
  未知说话人: 1 段未分配
```

## 排错

| 现象 | 处理 |
|---|---|
| 弹窗灰字「将用 T8 加载器的默认参数自动构造句柄」 | 正常提示：你没接线/没跑过，后端自己构造了句柄。想用自定义的设备/精度/驻留策略 → 接 `asr_model` 口并运行一次节点 |
| `识别失败 — AttributeError: 'PromptServer' object has no attribute 'last_prompt_id'` | 已修（旧版本）：T8 转写默认经 ComfyUI 进度钩子上报，而钩子读的 `last_prompt_id` 只在队列跑过 prompt 后才存在。现单次路径自带进度回调（不再建 `ProgressBar`），长音频路径会补齐该属性 |
| 按钮提示「没有可用的 ASR 模型」 | 说明**自动构造也失败了**，第二行会给原因：本地没有模型文件（跑 `scripts/download_models.py`）或 transformers 版本不满足（跑其 `scripts/check_transformers.py`） |
| 接了线却没沿用我的设置 | 重启 ComfyUI 会清掉运行时登记（句柄只在内存里），重跑一次节点即可；期间按钮仍可用，只是走默认参数 |
| 运行了但登记不上 | 弹窗会区分 `modelState=never-ran`（本会话没跑到 → 排队跑一次）/ `ran-without`（跑到了但模型口没交付 → 检查接线，加载器被 bypass 后解析出来就是空；控制台同时有「本次运行没有拿到 ASR 模型」一条 INFO） |
| 弹窗显示「识别失败：未找到 ASR 节点 …」 | ASR 包未安装 / 目录名不匹配；出片不受影响 |
| 片段全是灰色不可选 | 该缓存来源下这些片段都没有音轨——先生成，或把来源切到另一采 |
| 弹窗显示「时间轴解析失败」 | 前端/后端版本不一致（旧前端把 timeline 当字符串发）；硬刷新后重试 |
| 按钮不见了 | 任务类型不是 `r2v`（该按钮只在 r2v 工具栏显示） |
| 所有台词都判为「没说」 | 检查台词格式是否严格匹配；或说话人编号写错导致配对错位 |
| 尾部台词总被判漏 | 拼接时长超过 30 秒，确认走的是分块长音频路径 |
